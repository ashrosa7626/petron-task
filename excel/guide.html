Cigarette Counts to Excel

Excel connects to the count system and refreshes itself. Set this up once and every submitted count is in the workbook without anyone exporting anything.

Power Query

Nothing pushes. Excel asks the database for the counts, on open and on a timer. There is no file to send, no export step, and nothing for anyone to forget.

What arrives

One row per product per submitted trading day, from the vw_daily_reconciliation view.

ColumnWhat it holds
count_dateThe trading day closed — not the clock date the count was taken
product_idThe POS Item ID. The only safe join key
pluFor reading and checking the pack. Never join on it
short_nameProduct name as it appears on the shelf block
opening_packsThe previous submitted count’s closing
add_inStock added to the shelf during the day
closing_packsWhat was counted
sold_physicalopening + add_in − closing
sold_posWhat the POS says it sold
variance_packssold_physical − sold_pos
Drafts never arrive

A count reaches Excel only once it has been submitted. A half-finished count must never reconcile, so the view reads submitted counts only.

Set it up once

  1. Open a blank query
    In Excel: Data › Get Data › From Other Sources › Blank Query
  2. Paste the query below
    Home › Advanced Editor, delete what is there, paste all of it, then Done.
  3. Name it Counts
    The sheet formulas further down depend on this exact name.
  4. Close & Load
    If Excel asks about credentials for supabase.co, choose Anonymous.
  5. Turn on automatic refresh
    Data › Queries & Connections, right-click Counts › Properties, then tick Refresh data when opening the file and Refresh every 60 minutes. This is the whole automation.

    Columns  = "branch_id,count_date,staff_name,product_id,plu,short_name,pos_description,opening_packs,add_in,closing_packs,sold_physical,sold_pos,variance_packs",
    ColumnList = Text.Split(Columns, ","),
    PageSize = 1000,

    GetPage = (Offset as number) as list =>
        Json.Document(
            Web.Contents(
                BaseUrl,
                [
                    RelativePath = Resource,
                    Query = [
                        select = Columns,
                        order  = "count_date.desc,short_name.asc",
                        limit  = Text.From(PageSize),
                        offset = Text.From(Offset)
                    ],
                    Headers = [
                        apikey        = ApiKey,
                        Authorization = "Bearer " & ApiKey,
                        Accept        = "application/json"
                    ]
                ]
            )
        ),

    Pages = List.Generate(
        () => [Offset = 0, Rows = GetPage(0)],
        each List.Count([Rows]) > 0,
        each [Offset = [Offset] + PageSize, Rows = GetPage([Offset] + PageSize)],
        each [Rows]
    ),
    AllRows = List.Combine(Pages),

    AsTable =
        if List.IsEmpty(AllRows) then
            #table(ColumnList, {})
        else
            Table.ExpandRecordColumn(
                Table.FromList(AllRows, Splitter.SplitByNothing(), {"rec"}, null, ExtraValues.Error),
                "rec", ColumnList),

    Typed = Table.TransformColumnTypes(AsTable, {
        {"branch_id",       type text},
        {"count_date",      type date},
        {"staff_name",      type text},
        {"product_id",      type text},
        {"plu",             type text},
        {"short_name",      type text},
        {"pos_description", type text},
        {"opening_packs",   Int64.Type},
        {"add_in",          Int64.Type},
        {"closing_packs",   Int64.Type},
        {"sold_physical",   Int64.Type},
        {"sold_pos",        Int64.Type},
        {"variance_packs",  Int64.Type}

Reconciling against the POS

sold_pos and variance_packs come back blank today, because nothing loads the POS sales figures into the database yet. Until something does, do the POS side in the sheet.

The real fix, when it comes

A loader that writes the POS daily sales export into pos_sales_daily. After that, variance arrives already calculated and the two formula columns below become redundant. It needs a sample POS export — nobody has produced one yet.

1. A sheet named POS

Three columns, then Insert › Table, named POS.

sale_dateproduct_idqty_sold
2026-09-0910373228
2026-09-0910492222
Format product_id as Text first

Do this before pasting. If one side is text and the other a number, the lookup returns zero without complaining and every product reads as a perfect match — a clean sheet that is entirely wrong.

2. Two columns beside the Counts table

Click the first empty cell to the right of the table and add these. Columns added inside a query table survive refresh and fill down onto new rows.

pos_qty 
=SUMIFS(POS[qty_sold], POS[sale_date], [@count_date], POS[product_id], [@product_id])
variance 
=IF([@sold_physical]="", "", [@sold_physical] - [@pos_qty])

SUMIFS is deliberate: it returns 0 for a product the POS never sold rather than an error, and it copes with the POS listing a product twice in one day.

Reading the variance

0
Agreed. The shelf and the POS tell the same story.
+12
More left the shelf than was sold. Shrinkage, a miscount, or stock that went out without being recorded.
−40
The POS sold more than the shelf lost. Nearly always a delivery that was not recorded as add_in.
blank
Nothing to compare against. No previous count to open from. Every product shows this on its first count, and it fills in from the second consecutive day.

Two things that will skew variance

add_in is always zero

The count screen takes one number per product and no longer records deliveries. On any day stock went onto the shelf, sold_physical understates what was sold by the delivery quantity and shows as negative variance. Either record deliveries into add_in another way, or read negative variance on delivery days as expected.

Counts must be consecutive

opening_packs is the previous submitted count’s closing, whatever date that was. Skip a day and two days of sales silently fold into one, which reads as a large variance on the day after the gap.

If something goes wrong

Excel keeps asking for credentials
Data › Get Data › Data Source Settings, clear permissions for supabase.co, refresh, and choose Anonymous.
The table is empty
Normal before the first count is submitted. Check the results page shows a count marked Submitted — a draft will not appear here.
It stops at 1000 rows
The query pages past that on its own, so this means the M was truncated when pasted. Copy it again and check the last line is Typed.
PLUs have lost their leading zero
A column was typed as a number somewhere. Cosmetic only — PLU is never used to match anything — but the fix is type text in the query.
Dates fail to parse
The query pins its culture to en-US for this reason. If it still happens, check the "en-US" at the end of the last step survived the paste.
The key in these queries is read-only and already public in the app’s JavaScript. It grants read access and nothing more. Never paste a service key into a workbook.
