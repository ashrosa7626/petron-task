Merchandise Sales Report
Upload the POS daily sales PDF. The report prints as a scan with no text in it, so it is read by OCR. The only number taken from it is packs sold, and each one has to be confirmed by the report’s own figures before it is written — anything that cannot be is put in front of you with the scan beside it. Prices are read only as proof of the quantity and are never stored. Products that do not appear in the report sold nothing and are written as 0; without that they drop out of reconciliation entirely.
Kept with the day you load, so whoever looks at these numbers later knows who to ask. It is a name on the work, not a login — reading a printed report does not need an account.

PLU and Item ID disagree
The barcode printed beside the Item ID does not match the PLU held against that product. Two labels for the same pack, so one of them is wrong: either OCR misread a digit of the barcode, or the product table has the wrong PLU. Nothing is blocked — quantities are keyed on the Item ID and the PLU is never joined on — but a disagreement here is worth a look.
Item IDs not in the product table
These sold, but no product matches the ID. They cannot be written — the database requires a known product. Nothing here is silently dropped: decide whether to add the product first, or go ahead without these lines. They still count towards the Grand Total check above, because the POS counted them.
